# 小游戏美术与动画标准

> **定位**：视觉风格、资产规格、动画时长与手感的可执行标准。
> **适用**：`xechoz/<game>` 下的休闲 Web 小游戏（Phaser + `@mg/core`）。
> **关系**：玩法与界面规则见 [`game-design-standard.md`](game-design-standard.md)；技术流程见 [`game-development.md`](game-development.md)；硬规则以 `AGENTS.md` 为准。
> **优先级**：用户明确要求 > 既有设计系统（`@mg/core` 的 `theme`、`Button`、`Modal`）> 本文 > 文中示例数值。

---

## 0. 风格锁定

### 0.1 一个项目一种风格

禁止混合风格。以下组合全部不合格：
- 扁平色块 + 写实纹理
- 像素角色 + 矢量 UI
- 粗描边 + 无描边混用
- 高饱和角色 + 低饱和背景，但没有明确层级理由

### 0.2 推荐风格：扁平几何 + sticker

这是当前技术条件下**最容易**被 AI 稳定复现的风格，也是 `@mg/core` 已经实现的视觉语言：
- 单层色块，不做写实渐变
- 统一描边 + 底部 lip + 软投影（“贴纸”感）
- 圆角统一
- 光从左上来
- 图形由代码绘制，少用位图

`Button` 的 `primary` 变体就是这套语言的基准实现：`outline 3`、`lip 6`、`shadowAlpha 0.16`、`shadowOffset 10`、`gloss 0.12`。新素材必须和它对得上。

### 0.3 参考锚点

立项时写一个视觉参考（1 个游戏或 1 张图）。没有参考不开工，否则 AI 会漂移成“什么都有一点”的通用风格。

### 0.4 性格四旋钮

| 旋钮 | 收（中性 / 专业）    | 放（活泼 / 亲和）    |
| ---- | -------------------- | -------------------- |
| 字体 | 中性无衬线           | 圆体、有人格的无衬线 |
| 色彩 | 低饱和、单主色       | 高饱和、多强调色     |
| 圆角 | 小或无               | 大而统一             |
| 深浅 | 硬边、小阴影、浅色底 | 软阴影、色块、渐变   |

**四者必须同向。** 大圆角配硬直角卡片、低饱和配色配活泼字体，就是“廉价感”的来源。当前 `@mg/core` 的默认主题是“放”方向：高饱和、大圆角、贴纸阴影。游戏覆盖主题时必须整体同向，不能只换一个旋钮。

## 1. 调色板

### 1.1 来源

- 颜色只能来自 `theme`，或游戏通过 `GameDefinition.theme` 覆盖。
- 禁止在场景、动画、粒子代码里写十六进制色值。
- 新增颜色必须整族补齐，不在使用点 `lighten / darken`。

### 1.2 现有 token

| 用途           | token                                                               |
| -------------- | ------------------------------------------------------------------- |
| 背景           | `bg` / `bgAlt`                                                      |
| 棋盘 / 面板    | `board` / `boardAlt` / `panel` / `surface` / `surfaceAlt`           |
| 主色           | `accent` / `accentHover` / `accentAlt` / `accentWarm` / `accentInk` |
| 文字           | `text` / `textMuted` / `ink`                                        |
| 强调底色上的字 | `onAccent`                                                          |
| 危险           | `danger` / `dangerHover` / `onDanger`                               |
| 描边           | `borderSoft`                                                        |
| 遮罩           | `overlay`                                                           |
| 阴影           | `shadow`                                                            |
| 圆角           | `radius` / `radiusLarge`                                            |

### 1.3 数量限制

| 项           | 上限               |
| ------------ | ------------------ |
| 单屏色相     | ≤ 3                |
| 文字色       | ≤ 3 档             |
| 大面积彩色块 | ≤ 屏面 1/3         |
| 强调色面积   | ≤ 10%              |
| UI 灰阶      | ≥ 8 档（整族定义） |
| 每个语义色   | 独立色阶（5 档起） |

### 1.4 色阶规则

- 基准 500 能直接做按钮底色。
- 两端 900 / 100，中点 700 / 300，补齐 800 / 600 / 400 / 200。
- 明度越远离 50%，饱和度越高，否则两端发灰。
- 变亮朝 60° / 180° / 300° 旋转，变暗朝 0° / 120° / 240° 旋转，**不超过 20–30°**。
- 灰阶饱和度 2–10%，全站同一温度（偏冷或偏暖）。

### 1.5 对比度

| 场景                  | 最低                    |
| --------------------- | ----------------------- |
| 正文                  | 4.5:1                   |
| 大字（≥ 32 设计单位） | 3:1                     |
| 图标（信息性）        | 3:1                     |
| 描边与底色            | 1.5:1（仅装饰时可不计） |

彩色底上的次要文字：取**同色相**，降饱和、调明度，不用灰。灰在彩色底上会引入第三种色相，看着脏。

### 1.6 不只靠颜色

每个颜色编码必须有第二线索：图标、形状、位置、纹理、动画之一。

例：
- 危险不只是红色，还有尖角与抖动。
- 可收集不只是金色，还有闪烁与放大。
- 不可用不只是灰色，还有降透明度与禁用光标。

## 2. 形状与光

### 2.1 光源唯一

全项目光从左上来：
- 凸起：上缘亮、下缘暗，投影向右下。
- 内凹：上缘暗、下缘亮。
- 阴影 `offsetX = 0`，`offsetY > 0`。
- 不允许同一屏出现两个方向的阴影。

### 2.2 凸起的做法

`Button` 的贴纸语言：

| 层       | 做法                           |
| -------- | ------------------------------ |
| 描边     | `ink`，宽 3                    |
| 面色     | `accent`                       |
| 顶部高光 | 同色相更亮一档，透明度 0.12    |
| 底部 lip | `ink` 或暗一档，厚 6           |
| 投影     | `shadow`，偏移 10，透明度 0.16 |

**高光不用半透明白。** 半透明白会降低饱和度，看起来发灰；用同色相更亮的一档。

### 2.3 描边

| 项     | 规则                                |
| ------ | ----------------------------------- |
| 宽度   | 只用 3 与 6 两档                    |
| 用途   | 3 = 常规描边；6 = 底部 lip / 大元素 |
| 颜色   | `theme.ink` 或同色相深色，不用纯黑  |
| 一致性 | 同一屏描边宽度种类 ≤ 2              |

### 2.4 圆角

| 项   | 规则                                                          |
| ---- | ------------------------------------------------------------- |
| 档位 | ≤ 3 档                                                        |
| 来源 | `theme.radius`（18）/ `theme.radiusLarge`（28）；小元素可用 8 |
| 一致 | 同一屏圆角种类 ≤ 3                                            |
| 同向 | 小圆角配细线，大圆角可配粗线                                  |

### 2.5 剪影测试

任何角色、道具、可交互物，必须通过：
1. 纯黑填充。
2. 缩到 **32×32 设计单位**。
3. 仍能辨认是什么、朝向哪边。

不通过就重画轮廓，不要靠颜色和细节救。

### 2.6 图标

- 优先 Lucide，通过 `drawIcon` 使用。
- 只引入实际用到的图标。
- 记录许可证。
- 尺寸只用 24 / 32 / 48 三档，不缩放复用。
- 图标与同行文字的视觉重量相当；图标降一档对比，不要加粗。

## 3. 资产

### 3.1 程序化优先

| 优先级 | 方式                              | 适用                         |
| ------ | --------------------------------- | ---------------------------- |
| 1      | `Phaser.Graphics` 直接画          | 几何形状、棋盘、进度条、粒子 |
| 2      | `Graphics.generateTexture()` 缓存 | 需要重复绘制的复杂图形       |
| 3      | 位图 + atlas                      | 复杂纹理、Logo、图标、插画   |

规则：
- 能用 Graphics 画的，不用位图。
- 每帧重绘的 Graphics 必须改成 `generateTexture()` 缓存。
- 位图必须进 atlas，一个游戏一张。

### 3.2 尺寸与分辨率

| 项         | 规则                               |
| ---------- | ---------------------------------- |
| 设计空间   | 短边 720 设计单位                  |
| 导出倍率   | 2x（按最大展示尺寸）               |
| 最大画布边 | 4096（`MAX_CANVAS_EDGE`）          |
| 单张纹理   | 建议 ≤ 2048×2048                   |
| 图标       | 24 / 32 / 48 三档                  |
| 位图缩放   | 不缩小到 50% 以下，不放大超过 2 倍 |

### 3.3 命名

```
assets/<gameId>/<category>/<name>@2x.png
```

- `category`：`ui` / `char` / `prop` / `bg` / `fx`
- 全小写，连字符分隔
- 状态后缀：`-idle` / `-active` / `-disabled`
- 同一素材的帧放同一目录，用 `-01`、`-02` 编号

### 3.4 格式与体积

| 类型 | 格式                                |
| ---- | ----------------------------------- |
| 位图 | PNG（带透明）或 WebP                |
| 图标 | SVG 优先，运行时转纹理              |
| 音频 | OGG / MP3，见 `game-development.md` |
| 字体 | 中文系统栈；西文 OFL                |

体积：
- 单游戏首包 ≤ 2 MB gzip。
- 单张纹理 ≤ 2048×2048。
- 音频总量 ≤ 1.5 MB。
- 不打包 CJK 字体。

### 3.5 许可证

- 正式素材优先 CC0。
- 每个外部素材记录来源与许可证：`<name>.LICENSE.txt`。
- 不引入来源不明的素材。
- 运行时零外部请求：不使用 CDN、远程图片、远程字体。

### 3.6 占位策略

- 先用 Graphics 色块，形状定稿后再替换。
- 占位图必须有替换清单，上线前清空。
- 不允许直接拿最终美术当占位，避免“先画死再改”。

## 4. 视觉层级

| 层       | 特征                   | 对比               |
| -------- | ---------------------- | ------------------ |
| 背景     | 低饱和、低对比、少细节 | 饱和度 ≤ 40%       |
| 可交互物 | 高饱和、有描边、有投影 | 高于背景           |
| 反馈特效 | 短暂高亮、放大、粒子   | 最高，但 ≤ 600ms   |
| HUD      | 稳定、可读、不抢戏     | 高于背景，低于特效 |

规则：
- 背景不得使用高饱和纯色大面积铺满。
- 可交互物必须有至少一种非颜色线索（描边 / 投影 / 形状）。
- 特效只做短时高亮，不做常驻。
- 前景元素跨背景交界处时，加背景色描边或投影。

## 5. 动画

### 5.1 时长表

| 类型                   | 时长                  | 缓动               |
| ---------------------- | --------------------- | ------------------ |
| UI 按下反馈            | 80–120ms              | ease-out           |
| UI 面板进出            | 180–240ms             | ease-out / ease-in |
| 得分 / 奖励弹跳        | 300–450ms             | back-out           |
| 关卡切换               | 300–500ms             | ease-in-out        |
| 胜利 / 失败结算        | ≤ 700ms 后必须可操作  | —                  |
| **任何阻塞输入的动画** | **≤ 600ms（硬上限）** | —                  |

超过 600ms 的动画必须可跳过，或改成不阻塞输入。

### 5.2 缓动

| 场景 | 缓动                 |
| ---- | -------------------- |
| 进入 | ease-out（快进慢停） |
| 退出 | ease-in（慢起快走）  |
| 奖励 | back-out / spring    |
| 循环 | sine in-out          |
| 震动 | 线性，短促           |

禁止：
- 线性缓动做 UI 进出。
- 弹性缓动做高频反馈（会晕）。
- 同一屏出现 3 种以上缓动。

### 5.3 打击感

每个命中事件最多三层反馈：

| 层   | 做法                                 | 时长    |
| ---- | ------------------------------------ | ------- |
| 形变 | scale 1 → 1.15 → 1，或 squash 10–20% | ≤ 120ms |
| 颜色 | 闪白 / 闪亮                          | ≤ 80ms  |
| 粒子 | ≤ 12 个                              | ≤ 300ms |

可选第四层：hit stop 40–80ms。超过三层就是噪音。

### 5.4 粒子与震屏

| 项           | 上限           |
| ------------ | -------------- |
| 同屏粒子     | ≤ 40           |
| 单事件粒子   | ≤ 12           |
| 震屏幅度     | ≤ 4 设计单位   |
| 震屏时长     | ≤ 120ms        |
| 震屏开关     | 必须可关闭     |
| 常驻背景动效 | ≤ 2 个         |
| 常驻动效对比 | 低到不影响前景 |

### 5.5 减少动效

系统开启“减少动效”时：
- 去掉装饰性动画（背景漂浮、循环抖动、粒子）。
- 保留必要反馈（按下、命中、结算）。
- 不做全屏闪白、快速缩放、震屏。
- 转场改为淡入淡出或直接切换。

### 5.6 动画锁

- 动画锁只影响输入和表现，不改变规则状态。
- 结算动画期间必须停表。
- 恢复时给 3-2-1 倒计时。
- 动画不得吞掉玩家输入；输入缓冲 100–150ms。

## 6. 场景与镜头

### 6.1 入场

| 场景     | 要求                    |
| -------- | ----------------------- |
| 首次进入 | ≤ 1 秒，直接可操作      |
| 关卡开始 | ≤ 1 秒镜头移动或淡入    |
| 重开     | ≤ 300ms，不重复入场动画 |
| 菜单进出 | 180–240ms               |

### 6.2 结算

| 场景   | 要求                               |
| ------ | ---------------------------------- |
| 胜利   | 结果先出，特效后到；≤ 700ms 可操作 |
| 失败   | 定格 ≤ 0.5 秒展示死因，然后出结算  |
| 新纪录 | 颜色 + 图标 + 文案三重提示         |
| 跳过   | 任意点击可跳过动画，直接进结算     |

### 6.3 镜头

- 默认固定镜头，不做跟随。
- 需要震屏时按 §5.4。
- 不做缩放变焦，除非是核心机制。
- 转场只用淡入淡出或位移，不做花哨滤镜。

## 7. 验收

### 7.1 视觉检查

| 检查       | 通过标准                 |
| ---------- | ------------------------ |
| 剪影测试   | 32×32 纯黑可辨认         |
| 光照一致   | 全屏阴影同向             |
| 描边一致   | 同屏 ≤ 2 种宽度          |
| 圆角一致   | 同屏 ≤ 3 种              |
| 色相数量   | 单屏 ≤ 3                 |
| 对比度     | 正文 ≥ 4.5:1，大字 ≥ 3:1 |
| 非颜色线索 | 每个颜色编码都有第二线索 |
| 背景饱和度 | ≤ 40%                    |
| 占位图     | 上线前 0 处              |

### 7.2 动画检查

| 检查     | 通过标准                  |
| -------- | ------------------------- |
| 阻塞动画 | ≤ 600ms                   |
| 结算动画 | ≤ 700ms 后可操作          |
| 同屏粒子 | ≤ 40                      |
| 震屏     | ≤ 4 单位、≤ 120ms、可关闭 |
| 常驻动效 | ≤ 2 个                    |
| 减少动效 | 开启后仍可玩              |
| 输入缓冲 | 100–150ms                 |
| 动画锁   | 不改变规则状态            |

### 7.3 P0

- 光照方向不一致
- 描边宽度混用超过 2 种
- 单屏色相 > 3
- 正文对比度 < 4.5:1
- 占位图上线
- 动画阻塞输入 > 600ms
- 震屏不可关闭
- 减少动效开启后不可玩
- 使用来源不明的素材
- 运行时加载外部图片 / 字体

## 8. 反模式

| 反模式              | 后果                       |
| ------------------- | -------------------------- |
| 混合风格            | 廉价感，且 AI 无法稳定复现 |
| 半透明白做高光      | 发灰、发脏                 |
| 每个元素一套阴影    | 层级混乱                   |
| 描边宽度随手定      | 画面不统一                 |
| 用颜色当唯一信号    | 色盲不可用，小屏看不清     |
| 位图放大 3 倍       | 糊成一团                   |
| 每个精灵独立纹理    | draw call 爆炸             |
| 每帧重绘 Graphics   | CPU 打满                   |
| 常驻粒子 / 循环抖动 | 抢戏、耗电、晕             |
| 结算动画超过 1 秒   | 打断“再来一局”             |
| 装饰性动画不可关    | 无障碍不合格               |
